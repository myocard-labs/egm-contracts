# myocard-egm-contracts

> Cross-language data-format schemas + validators for the myocard-labs intracardiac EGM project.

Part of the [myocard-labs](https://github.com/myocard-labs) cardiac signal processing toolkit. See the meta repo [`intracardiac-platform`](https://github.com/myocard-labs/intracardiac-platform) for the project pitch and the dependency graph.

---

## Why

This package owns the **schemas** for every data format used across the project — synthetic banks, IAFDB banks, training-run records, and the deployment-time model metadata sidecar. It is the slowly-changing interface boundary between producers (`iafdb-pipeline`, `synthetic-egm-pipeline`, `egm-classifier`) and consumers (`egm-data`, `egm-studio`).

**JSON-Schema-first.** The master truth for every format is a JSON Schema (Draft 2020-12) file. Pydantic models (Python) are codegen'd from those schemas; C++ structs (eventually, for the TensorRT-targeted deployment) will be codegen'd from the same source. The schema files are the only place you edit when a format changes.

Validators (`validators/`) open actual HDF5 / CSV / JSON files and check them against the schema. The HDF5-to-JSON-Schema mapping is contained inside the validator code so the schema files stay declarative.

## How to consume

### Python

```python
from myocard_egm_contracts import iafdb_bank
from myocard_egm_contracts.validators import validate_iafdb_bank

# Type-safe construction (raises pydantic.ValidationError on bad input).
bank_doc = iafdb_bank.IafdbBank.model_validate(some_dict)

# File-level conformance check against the on-disk HDF5.
result = validate_iafdb_bank("iafdb_v1.h5")
if not result.ok:
    for issue in result.issues:
        print(issue)
```

### C++ (eventually)

When the C++ deployment chat lands, headers will be generated by `python codegen/gen_cpp.py` into `src/myocard_egm_contracts/_generated/cpp/`. Consumption pattern (planned):

```cmake
# In your CMake project
FetchContent_Declare(
  myocard_egm_contracts
  GIT_REPOSITORY https://github.com/myocard-labs/egm-contracts.git
  GIT_TAG        v0.3.0  # pin to a release tag
)
FetchContent_MakeAvailable(myocard_egm_contracts)
target_link_libraries(my_target PRIVATE myocard_egm_contracts::headers)
```

```cpp
#include <myocard_egm_contracts/iafdb_bank.hpp>

auto bank = myocard::egm_contracts::IafdbBank::from_json(payload);
```

Header-only; no compiled library shipped.

## Schemas

The eight formats currently described:

| Schema | On-disk format | Producer | Consumer(s) |
|---|---|---|---|
| `synthetic_bank` | HDF5 | `synthetic-egm-pipeline` | `egm-data` (converted to ClassifierBank) |
| `iafdb_bank` | HDF5 | `iafdb-pipeline` | `egm-data` (converted to ClassifierBank), **C++ inference benchmark** |
| `noise_bank` | HDF5 | `iafdb-pipeline` (any real EGM dataset) | `synthetic-egm-pipeline` mixer |
| `noise_bank_run_record` | JSON sidecar to noise_bank | `iafdb-pipeline` | reproducibility audits, paper methods |
| `run_record` | JSON (`run.json`) | `egm-classifier` (training) | `egm-studio`, paper figures |
| `metrics` | CSV (`metrics.csv`) | `egm-classifier` (training) | `egm-studio`, paper figures |
| `model_metadata` | JSON sidecar | `egm-classifier` (export) | TensorRT C++ inference runtime |

Per-trace prediction outputs are no longer their own format — they live inside the ClassifierBank produced by the eval step (in `egm-data`). There is no aggregate-metrics format: the dedicated `hybrid_eval_metrics` schema was removed in 0.4.1 (see `docs/schemas/hybrid_eval_metrics.md`). Any evaluation scores are computed at analysis time in `egm-studio` from the ClassifierBank rather than persisted as a contract.

"Hybrid" follows the cardiac-ML convention from Sánchez et al. 2021 — mixed in silico + in vivo data. A hybrid *evaluation* (scoring against mixed synthetic positives and labeled real negatives) would need labeled real EGM data, which the project lacks — IAFDB has no fibrosis labels — so it cannot be run today. The synthetic bank itself is not called "hybrid" even when it has IAFDB-noise conditioning applied, since the labels are 100% synthetic. See `docs/schemas/` for the narrative explanation of each schema and `project/known_issues.md` for terminology and evolution notes.

## Adding or changing a schema

1. Edit the `.schema.json` file in `src/myocard_egm_contracts/schemas/`. **This is the only place the change happens.**
2. Run `python codegen/gen_python.py` to regenerate the Python models.
3. (Eventually) run `python codegen/gen_cpp.py` to regenerate C++ headers.
4. Update any validator if the HDF5 ↔ JSON Schema mapping is affected.
5. Update / add tests under `tests/` to cover the new fields.
6. Commit the schema change **and** the regenerated `_generated/` files. CI will reject any drift.

**Breaking changes** bump the `schema_version` constant inside the schema and the package version's minor (pre-1.0) or major (post-1.0). Coordinated with consumers per the cross-component contract rules.
